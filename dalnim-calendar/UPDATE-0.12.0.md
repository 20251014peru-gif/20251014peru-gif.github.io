# 0.12.0 · 확인·복기와 예측 검증 연결

2026-09-28. 개인 투자·기록 전용 캘린더. 업무일지와 가족 기능은 추가하지 않는다.

## 사용법

- 기록보관실의 확인 항목을 누르면 최신 원본을 읽는다. 확인 날짜, 미확인/확인 중/완료/보류, 결과, 다음 행동을 수정하고 **변경 저장**을 누른다.
- 완료에는 결과가, 보류에는 이유가 필요하다. 완료는 확인 업무 종료이며 예측 적중이 아니다.
- **예측 검증** 연결은 유튜브 예측의 검증 기한/대기중·적중·빗나감·판정불가/판정 근거를 같은 원본에 저장한다. 자동 채점 투자 예측은 원본 JSON과 채점 결과를 읽고 재알림을 예약한다. 자동 채점 원본 자체의 수정은 원본 프로그램에서 한다.
- **나중에 다시 알림**은 1/3/6/24시간 또는 날짜와 5분 다이얼로 예약한다. 원래 확인 날짜는 바꾸지 않는다.
- 완료·보류·판정 완료 시 남은 예약을 취소한다. 기록보관실이나 유튜브에서 직접 변경해도 클라우드 예약 함수가 매분 확인하고, 발송 직전 원본을 다시 읽는다. 다시 미확인으로 바꿔도 취소했던 알림을 임의로 되살리지 않는다.
- 데이터 연결에서 기록보관실과 예측을 각각 켜고 끌 수 있다. 화면 연결 끄기는 이미 예약한 알림 취소가 아니다.
- 동시 수정 충돌 시 입력을 유지하고 다른 화면의 최신 내용을 표시한다. 비교 후 필요한 내용을 합쳐 다시 저장한다. 저장 오류 시에도 입력은 유지한다.

## 데이터 계약과 보존

- 현재 확인 일정의 기준은 `record_followups`. `records.checks`, `reviewAt`, `records_todos`를 다시 완료 기준으로 쓰지 않는다. 원본 기록과 옛 완료 표식은 수정·삭제하지 않는다.
- 확인 저장은 기존 `revision` 검사 및 `record_followup_reviews` 이력을 함께 사용한다. 전환 규칙은 invest `f636cef7`의 `js/followups-core.mjs`를 `server/linked-investments/followup-contract.mjs`에 출처와 함께 고정했다. 원본 규칙이 바뀌면 계약 비교 시험 후 갱신한다.
- 유튜브는 `youtube_predictions`의 `검증기한`, `상태`, `판정근거`만 의도한 값으로 바꾸며 원문을 보존한다. 문서 지문으로 원본 앱의 동시 변경도 감지한다. 재시도 표식 2개와 공간 내부 `integrationHistory`에 수정 이력을 남긴다.
- 자동 채점 원본: invest의 `raw/predictions.json`, `analysis/scores.json`. 읽기만 한다. 조회 실패와 빈 데이터를 구분하며 유튜브 연결을 계속 제공한다.
- 이전 `investment-check:*`/`investment-review:*` 알림은 확인·복기의 보존된 `legacy` 연결로 최신 항목에 대응한다. 추측으로 다른 질문에 연결하지 않는다. 이미 없는 원본은 예약을 취소한다. 네트워크 오류는 삭제로 해석하지 않는다.
- 원문과 확인 항목을 캘린더 데이터로 복제하지 않는다. 다시 알림만 기존 `dalnimSpaces/family/events`에 저장한다.

## 클라우드 운영과 비용

- 웹: https://20251014peru-gif.github.io/dalnim-calendar/
- API: https://calendarapi-ng2m4osziq-du.a.run.app
- Firebase `my-system-25497`, `asia-northeast3`, 기존 `dalnim-calendar` codebase만 배포한다. 새 서비스, AI 호출, 외부 알림 앱은 추가하지 않는다.
- `calendarApi`, `calendarReminderSweep`, `investmentReminderSweep`의 변경이므로 서버 재배포가 필요하다. 서버 먼저, 웹 화면 다음 순서로 배포한다.
- 열린 화면은 30초마다 선택한 연결을 갱신하고, 다시 화면으로 돌아올 때 갱신한다. Firestore 읽기 비용은 연결 자료 수와 열린 화면 수에 따라 늘어난다. 컬렉션당 5,000개까지 읽으며 초과는 조용히 자르지 않고 오류로 표시한다.
- 기존 매분 예약 함수가 재알림 원본 상태를 확인한다. 일반 투자 요약은 매일 한국 시간 10:15/16:15에 현재 미완료 항목을 읽으며, 미래 재알림을 직접 예약한 항목은 그 시간까지 요약에서 제외한다.
- 서버 발송 접수는 실제 휴대폰 수신과 다르다. 휴대폰 실기기의 권한·네트워크·절전 상태와 실제 수신은 별도로 확인해야 한다.

## 검증과 복구

단위/통합 시험은 합성 자료로 현재 날짜/상태 투영, 결과 필수, 충돌 거부, 첨부·원문 보존, 이력, 재시도, 원본 완료에 따른 취소, 원본 조회 실패, 예측 원본 분리를 검사한다. 격리 브라우저에서 저장/재접속/충돌/오류 후 입력 유지/예약·취소/모바일을 검수한다. 실제 배포·실자료 검증 결과는 작업 완료 기록과 구분한다.

기존 원문·확인 기록은 각 원본 앱의 백업을 이용한다. 캘린더 내보내기는 캘린더 자체 일정·재알림의 백업이며 다른 앱의 전체 백업을 대신하지 않는다. 배포 전 서버 설정과 영향을 받는 Firestore 문서 사본을 비공개 Cloud Shell에 보존한다. 사진 파일은 이번에 수정하지 않으며 전체 사진 백업으로 부르지 않는다.

복구는 직전 운영 커밋 `d9a11a5`의 달님 캘린더 서버/웹 소스를 사용한다. 원본 확인 상태를 지우거나 구형 `checks`로 다시 이관하지 않는다. 구형 화면의 완료 버튼은 새로운 결과 필수 규칙과 호환되지 않으므로 코드 복구 시 그 제한을 명시한다.

공식 참고: [Firestore 트랜잭션](https://firebase.google.com/docs/firestore/manage-data/transactions), [함수별 배포](https://firebase.google.com/docs/functions/manage-functions).
