# 0.3.0 업데이트

이전 버전에서 문서로 남아 있던 미구현 항목 중 4가지를 구현했습니다: 반복 일정의 개별 발생 수정, 오프라인 저장 대기열, 미확인 알림 재발송, 가족 초대. 문자(SMS) 대체 발송은 유료 API 계정이 필요해 이번 범위에서 제외했습니다.

## 반복 일정의 개별 발생(occurrence) 수정

- 캘린더·하루 흐름·알림함에서 반복 일정을 열면 저장하거나 삭제할 때 **이 날짜만** / **전체 반복** 중에서 고를 수 있습니다.
- "이 날짜만"은 제목·메모·장소·진행 상태·미리 알림만 그 날짜에 한해 바꿉니다. 시간 이동은 아직 지원하지 않습니다(전체 반복의 시간을 바꾸는 것은 기존과 동일하게 가능합니다).
- 데이터는 마스터 일정의 `exceptions` 맵에 발생 날짜를 키로 저장합니다. 삭제는 `deletedAt`만 기록해 그 날짜만 숨기고 나머지 반복은 그대로 유지합니다.
- 서버 예약 알림(`server/schedule.mjs`)도 같은 예외를 읽어 그 날짜만 건너뛰거나 다른 알림 시간을 적용합니다.
- 개별 삭제한 발생을 다시 불러오는 화면(복원)은 아직 없습니다. 필요하면 같은 날짜·시간으로 새 일정을 추가해야 합니다.

## 오프라인 저장 대기열

- 클라우드 모드에서 저장 중 네트워크가 끊기면 오류로 막지 않고 이 기기의 대기열(IndexedDB)에 넣습니다. 화면에는 "오프라인 저장 대기 · N건"으로 표시하고, 저장 완료로 표시하지 않습니다.
- 온라인으로 돌아오면(15초 주기 갱신 또는 브라우저의 online 이벤트) 대기열을 순서대로 다시 보냅니다.
- 재전송 중 서버가 진짜로 거부하면(예: 다른 기기가 먼저 수정해 리비전이 어긋난 경우) 그 항목은 대기열에서 지우고 사용자에게 알립니다. 자동으로 덮어쓰지 않습니다.
- 이 기기에서 끊긴 동안의 대기열이며, 컴퓨터 자체가 꺼져 있는 것과는 다릅니다. 실사용 서버와 예약 알림은 기존처럼 컴퓨터 전원과 무관하게 클라우드에서 동작합니다.

## 미확인 알림 재발송(무료 웹 푸시만)

- 알림을 보낸 뒤(서비스 접수 기준) 사람마다 개별적으로, 링크를 열어 확인하지 않았으면 10분 뒤, 그래도 확인하지 않았으면 다시 10분 뒤(최대 2회 재발송, 총 3회 발송)까지 다시 보냅니다.
- 이미 확인한 사람에게는 다시 보내지 않습니다. 확인 여부는 사람마다 따로 기록합니다.
- 문자·전화 등 다른 채널로의 대체 발송은 구현하지 않았습니다(유료 API 계정 필요, 이번 범위 제외).

## 가족 초대

- 설정 → 가족 초대에서 공간 관리자(owner)가 이메일과 역할(편집 가능/보기만)로 초대를 만들면 공유 가능한 링크가 나옵니다(7일 후 만료, 링크는 직접 전달해야 합니다 — 이메일 발송 기능은 없습니다).
- 받는 사람이 그 이메일 계정으로 로그인한 뒤 링크를 열면 서버가 초대한 이메일과 로그인 계정의 이메일이 같은지 확인하고 공간 구성원으로 등록합니다.
- 대기 중인 초대는 관리자가 언제든 취소할 수 있습니다.

## 검증

- `npm test` (node --test): 모델·정책·예약·워크로그·알림·클라우드 저장소 테스트 **43개 통과** (신규 11개 포함: 개별 발생 예외 3개, 예약 알림 예외 처리 2개, 정책/초대 검증 2개, 오프라인 대기열 3개).
- `node --check`로 서버·클라이언트 신규/수정 파일 문법 검사 통과.
- 위 테스트는 모두 로컬 유닛 테스트입니다. 다음은 **아직 검증하지 않았습니다**:
  - 실제 Firebase 프로젝트에 `calendarApi`/`calendarReminderSweep` 재배포 후의 동작(초대 라우트·재알림 라우트는 같은 함수에 새로 추가된 것이므로 재배포가 필요합니다).
  - 실제 가족 이메일로 초대 링크를 보내고 그 계정으로 수락하는 전체 과정.
  - 실제 네트워크 단절/복구 상황에서 오프라인 대기열의 자동 재전송.
  - 실제 휴대폰에서 미확인 재알림(10분 간격)이 지연 없이 오는지.
  - 회사 PC/집 노트북을 모두 끈 상태에서 위 기능들이 여전히 동작하는지(설계상으로는 서버가 처리하므로 동작해야 하나, 실기기 시험 전에는 완료로 보지 않습니다).

로컬 시험 성공을 운영 완료로 보고하지 않습니다. 실사용 전환 전 DEPLOYMENT.md 5번 절차(두 기기 동시 수정, 가족 권한, 알림 지연 등)를 다시 수행해 주세요.
