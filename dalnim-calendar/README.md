# 달님 캘린더 0.7.3

기존 디자인 기준(밝은 화면·파란 주요 행동·의미 있는 색·점진적 상세)을 반영한 독립 캘린더 첫 버전입니다.

실사용 주소: https://20251014peru-gif.github.io/dalnim-calendar/

본인 계정으로 로그인하면 Firebase Firestore에 저장합니다. PC를 꺼도 클라우드 API와 예약 알림 서버는 동작합니다. 시작 순서는 [START-HERE.md](START-HERE.md)를 참고하세요.

## 지금 사용 가능

- PC 주간 시간표, 일간·월간·연간·목록 보기.
- 일정 추가·수정·드래그 이동·길이 변경·삭제·휴지통 복원.
- 매일·매주·매월·매년 반복. 저장·삭제 시 "이 날짜만" 또는 "전체 반복" 중 선택(개별 발생 예외).
- 검색, 분류 표시, 분류 추가·이름·색상 변경.
- 워크로그·투자·가족 상세 블록 켜기/끄기. 꺼도 기록 유지.
- 워크로그 JSON 가져오기, 일정 JSON 백업, 인쇄.
- 모바일 일간 화면과 홈 화면 설치 기반.
- 로컬 체험은 IndexedDB 저장, 동시 탭 수정 충돌 검사.
- 클라우드 저장 중 네트워크가 끊기면 기기에 대기열로 보관했다가 연결되면 자동 재전송(오프라인 큐). 대기 중에는 "오프라인 저장 대기"로 표시하고 저장 완료로 표시하지 않습니다.
- 알림을 보냈지만 앱에서 열어 확인하지 않으면 10분 간격으로 최대 2회 다시 보냅니다(문자 대체 없이 무료 웹 푸시만 재발송).
- 설정 → 가족 초대: 관리자가 이메일과 역할(편집/보기)로 초대 링크를 만들고 취소할 수 있습니다. 초대받은 사람이 그 계정으로 링크를 열어 로그인하면 공간에 자동으로 등록됩니다.
- 별도 프로그램 [투자 기록보관실](https://github.com/20251014peru-gif/invest)(같은 Firebase 프로젝트)의 날짜 있는 기록·할 일을 읽기 전용으로 가져와 "투자 노트" 분류로 함께 보여줍니다. 이 캘린더에서는 수정·삭제할 수 없고, 공간 관리자(owner) 계정에만 보입니다. 자세한 내용은 [업데이트 안내](UPDATE-0.4.0.md) 참고.

실사용 버전은 로그인 후 본인의 서버 일정을 표시합니다. 로컬 체험 모드에서만 예시 일정이 표시됩니다. 서버 연결 실패 시 체험 저장소로 자동 전환하지 않습니다.

## 0.2에서 추가된 연결 체험

`connected.html`을 열면 워크로그 형식의 업무·업무예정 입력 화면이 나옵니다. 이 화면과 **로컬 체험 모드** 달님 캘린더는 같은 IndexedDB 기록과 버전을 사용합니다. 실사용 서버 일정과는 분리되어 있습니다. 제목·시간·상태·메모·상세 항목 수정과 삭제·복원이 서로 반영되고, 오래된 폼으로 저장하면 충돌을 알립니다. 첨부 목록·자재·사용자 정의 필드는 그대로 보존합니다.

이것은 **기존 운영 worklog.html에 연결된 화면이 아니라, 공통 연결 계약을 사용하는 별도 체험 화면**입니다. 실제 워크로그의 Firebase 저장 경로 교체·데이터 이관은 아직 활성화하지 않았습니다. 업무·업무예정 외 종류는 기존 JSON 가져오기만 지원합니다.

알림함에는 서버·기기 권한 상태, 기기 등록/해제, 테스트 알림, 서버 접수/열기 확인 기록 UI가 추가되었습니다. 실제 서버와 기기가 연결된 뒤 사용할 수 있습니다.

## 실행

Node.js 22 이상에서 이 폴더의 터미널을 열고:

    npm start

로컬 체험을 다시 사용하려면 src/config.js의 apiBase를 빈 문자열로 바꾼 복사본에서 http://127.0.0.1:4173 을 엽니다. 프런트엔드 미리보기에는 npm install이 필요하지 않습니다. HTML을 더블클릭(file://)하면 ES 모듈과 저장소 제약으로 정상 실행되지 않습니다.

공개 웹 파일과 개인 데이터 공개는 별개입니다. 데이터는 로그인·공간 권한을 검사하는 서버 API를 통해서만 접근합니다. 기본 공간에는 본인 계정만 등록되어 있습니다.

다른 페이지에 삽입:

## 아직 활성화되지 않은 것 · 미검증

- 가족 계정 추가: 초대 링크를 만들고 받는 서버·화면 기능은 0.3.0에 추가했습니다. 실제 가족 이메일로 초대를 보내고 그 계정으로 로그인해 공간에 들어오는 것은 아직 실기기로 검증하지 않았습니다.
- 휴대폰 실제 수신 검증: 서버·발송 키는 배포했습니다. 각 기기의 알림 권한·구독 등록과 수신 확인, 그리고 0.3.0의 미확인 재알림(10분 간격 최대 2회)이 실제 휴대폰에서 지연 없이 오는지는 검증하지 않았습니다.
- 문자(SMS) 대체 발송: 구현하지 않았습니다. 유료 SMS API 계정이 필요합니다. 지금은 웹 푸시 재발송까지만 지원합니다.
- 기존 워크로그와 완전한 양방향 연동: 현재 JSON 가져오기만 구현.
- 실시간 투자 데이터 수집, 첨부파일 업로드.
- 반복 일정의 개별 발생(occurrence) 수정: 0.3.0부터 저장·삭제 시 이 날짜만 바꾸는 것을 지원합니다. 다만 개별 발생의 시간 이동(그 날짜만 다른 시간으로 옮기기)은 아직 지원하지 않고, 개별 삭제한 발생을 휴지통에서 복원하는 화면도 없습니다.
- 클라우드 모드의 오프라인 수정 큐: 0.3.0에서 추가했습니다(연결이 끊기면 기기에 대기했다가 재연결 시 자동 전송). 로컬 유닛 테스트로만 확인했고, 실제 네트워크 단절/복구 상황에서의 동작은 검증하지 않았습니다.
- 다른 시간대로 여행할 때 반복 시간 유지의 브라우저/서버 일치 검증. 초기 실사용 시간대는 Asia/Seoul을 권장합니다. 개별 발생 예외의 날짜 키도 같은 제약을 받습니다.
- 이 문단의 새 기능은 모두 로컬 유닛 테스트(43개)만 통과한 상태이며, 실제 Firebase 배포·계정·휴대폰 통합 검증은 거치지 않았습니다. 실사용 전에는 DEPLOYMENT.md의 검증 절차를 다시 수행해야 합니다.

체험 공간에서는 알림 시간을 저장해도 실제 알림이 발송되지 않습니다. 실사용 서버의 예약 알림은 컴퓨터 전원과 관계없이 처리됩니다. 휴대폰 표시 여부는 기기 설정과 연결 상태에 영향을 받습니다.

## 색상과 화면 디자인

펄 화이트 바탕에 연핑크·블루·세이지 민트를 조합했습니다. 주요 버튼과 날짜 선택은 블루, 가족 일정은 로즈, 투자 일정은 민트로 구분합니다. 일정 글자는 짙게 유지하고 배경만 은은하게 물들였습니다.

`theme.css`는 색상·표면·그림자·상호작용을 담당하는 독립 디자인 파일입니다. 이 파일을 바꾸거나 연결을 제거해도 일정 데이터와 기능은 유지됩니다. 저장된 사용자 지정 분류 색상은 덮어쓰지 않습니다. 분류의 초기 색상은 `src/app.js`와 해당 블록의 `src/modules/`에 정의되어 있습니다.

0.7.3: 사진이 업로드될 Storage 버킷 이름을 실제 값(`my-system-25497.firebasestorage.app`)으로 수정 — 0.7.0에서 다른 앱의 예전 별칭 이름(`.appspot.com`)을 그대로 가져다 써서, 재배포됐다면 사진 업로드가 전부 실패했을 것입니다. Firebase 함수 재배포 완료, 버킷 CORS·서비스 계정 쓰기 권한까지 직접 확인했습니다.
